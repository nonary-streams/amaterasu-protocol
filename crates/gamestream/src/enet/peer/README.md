# Bounded ENet server peer

`Peer` implements one socket-independent host association. The managed owner supplies a monotonic millisecond clock, filters an explicitly authorized IP/port, and drains output datagrams and events. `receive` reports `associated: true` only after an expected CONNECT hint or a valid associated peer/session header. A CONNECT hint is not authentication: the owner must require the negotiated authenticated control envelope before dispatching application actions. Never learn an arbitrary destination from a packet and reflect these outputs to it.

The peer negotiates up to 48 channels and an MTU of 576–4096 bytes. It echoes the opaque connect ID and throttle parameters, assigns ENet session bits, and emits `Connected` after acknowledgement of VERIFY_CONNECT. Reliable messages use separate channel sequences, explicit acknowledgements, an outgoing byte window negotiated by CONNECT, and bounded exponential retransmission with a rotating 16-command poll budget. Outgoing messages fragment at the negotiated MTU; the receiver reassembles reliable and unreliable fragments and checks overlapping byte ranges and conflicting metadata. Unreliable messages wait for their reliable baseline. Their sequence is numeric within that baseline; following ENet, outgoing unreliable sequence exhaustion promotes the next message to reliable and resets the unreliable counter instead of wrapping it. Unsequenced messages use a 1,024-sequence duplicate window. Disconnect, idle timeout, periodic ping, and retransmission preserve the supplied clock rather than reading wall time.

`can_send(channel, length, delivery)` is a nonmutating admission check for the same thread's immediate `send`. `Busy` consumes neither a sequence nor queued payload. The control owner must perform this check before encrypting with a fresh invocation number; if a subsequent unexpected send error occurs, it must fail the stream rather than rewind cryptographic state. A reliable command accepted into the peer may wait for the remote byte window before transmission. Retransmission reuses the same message bytes with a new ENet sent-time field.

The engine bounds messages to 65,539 bytes, fragments and outstanding reliable commands to 128, sequence lookahead to 128, outgoing datagrams to 128 / 256 KiB, retained incoming assemblies to 128 / 256 KiB, and delivered events to 256 / 1 MiB. Application queues outside the engine need their own limits. Admission clones bounded state and commits a whole datagram only after all commands succeed; rejected commands cannot leave partial acknowledgements or deliveries. This deliberately spends bounded copying work to simplify atomic admission. It has not been throughput qualified.

An incomplete reliable message or missing predecessor held for five seconds terminates the peer rather than forgetting already acknowledged data. Incomplete unreliable messages expire after five seconds. Defaults are a five-second handshake deadline, a 15-second idle deadline, 250 ms initial retry (exponential, capped at two seconds), and one-second ping interval. The clock must not move backwards. The owner must call `poll` and drain queues regularly; persistent output congestion eventually hits a bounded timeout. Remote disconnect discards previously queued application datagrams, emits one disconnect event, and retains its acknowledgement; repeated remote disconnect can be acknowledged again. Closing the owner may abort without graceful protocol completion.

This is a bounded control-transport profile, not a complete replacement for ENet's adaptive congestion manager. Bandwidth and throttle commands are accepted and acknowledged as metadata; bandwidth shaping and RTT-adaptive congestion/throttle behavior are not implemented. Compression, checksums, oversized unsequenced fragmentation, peer migration, reconnecting an existing peer object, and arbitrary peer discovery are unsupported. Create a new peer only through an independently authorized session lifecycle. There is no socket, cryptographic authentication, launch authorization, RTSP orchestration, or production Moonlight readiness claim here.

The implementation was written independently from behavior observed in the pinned Moonlight ENet fork. Tests cover atomic malformed-datagram rejection, hint/session filtering, channel ordering and deduplication, reverse fragment assembly and overlap rejection, byte-window backpressure, reliable-gap timeout, retry, and disconnect acknowledgement loss. The ignored `pinned_c_client_handshake_fragment_echo_and_disconnect` test uses the actual separately compiled pinned C ENet client (`AMATERASU_ENET_ORACLE`): 48-channel connection, negotiated MTU 900, reliable 11-byte and fragmented 2,000-byte echoes on separate channels, and graceful disconnect. See the parent ENet README for the reproducible oracle build.

## Transaction and memory qualification

The queue byte limits count payload storage, not all allocator overhead. In addition, pending reliable commands retain at most 128 MTU-bounded payload copies, with at most 16 sent-time entries each. Reassembly retains at most 128 groups, each with at most 128 optional piece descriptors; nonoverlapping copied piece bytes cannot exceed the group's declared total. Event payloads, output datagrams, channel maps (at most 48), and the 1,024-entry unsequenced history are bounded separately. A receive transaction owns one cloned peer plus the decoded datagram (at most 4,096 bytes / 32 commands). Before the final admission check, a malicious transaction may temporarily create up to 32 additional bounded assemblies; no assembly allocates its declared full payload until all actual pieces cover it. Peak working memory therefore includes that clone and bounded transient metadata and is greater than the retained payload byte caps. This is bounded memory, not a claim of a 256 KiB total peer footprint.

Qualification tests exercise 128 maximum-descriptor groups, the declared-payload byte cap, a full delivery queue with acknowledgement withheld until successful retry, conflicting reliable/fragment sequences, malformed complete fragment coverage, and repeated retransmission with a bounded sent-time history. Closed-state coalesced data is rejected atomically. A modern control integration test reorders a fragmented envelope and its reliable successor around a different channel, then uses one shared `ControlOpener` to accept each global sequence once and reject a replay on another channel. ENet sequencing alone is not the authenticated replay boundary.
